# v0.3 当前进度评估与下一步计划

> 当前日期：2026-05-30
> 策划基准：《五四三二一》基础策划案 v0.3
> 评估对象：当前 `main` 分支可运行原型

---

## 1. 结论

当前项目已经具备 v0.2 级别的可玩 Demo 闭环：

```text
扫雷地图 -> 房间移动 -> 搜刮 / 怪物 / 事件 -> 撤离 / 失败 -> 局外金币 / 装备 / 天赋
```

但 v0.3 的设计目标已经升级为完整搜打撤系统规则版：

```text
普通随机模式 + 评委手排模式 + 地图状态拆分 + 协议压力 + 背包负重 + 仓库 + 轻量走位战斗
```

因此当前状态可以判断为：

| 维度 | 当前完成度 | 判断 |
| --- | ---: | --- |
| v0.2 Demo 闭环 | 75%~85% | 已可试玩，主要缺表现和体验打磨 |
| v0.3 系统规则 | 35%~45% | 已有骨架，但关键规则仍未切换 |

下一步不建议直接重写怪物战斗。应先把地图模式、格子状态、协议压力和物品背包这些系统地基打稳。

| 模块 | v0.3 目标 | 当前实现 | 差距 |

## 4. v0.3 技术风险排序

### 高风险

1. **地图模式重构**
   - 普通模式和评委模式会影响 `Minefield.New()` 的配置入口。
   - 需要兼容现有测试和 Demo 入口。

2. **地图状态拆分**
   - `revealed` 当前同时承担“显示信息”和“玩家到达”的职责。
   - v0.3 要求扫描、探索、清理分离。

3. **背包 / 仓库**
   - 会改变搜索、宝箱、结算、失败保底和局外存档。
   - 需要谨慎迁移，避免把现有闭环打断。

4. **怪物轻量战斗**
   - 从检定系统改为房间内动作判定，涉及输入、碰撞、动画、受伤、死亡掉落。
   - 不应和地图状态 / 背包重构同时做。

### 中风险

1. 协议压力系统。
2. 评委模式调参面板。
3. 通用事件框架。
4. 失败保底 UI 重做。

### 低风险

1. 当前房间雷数 HUD 强化。
2. 素材命名清理。
3. 图例、提示文案、结算文案调整。
4. 协议面板文案和颜色调整。

## 5. 下一步开发顺序

### 阶段 0：文档和资源清理

目标：让仓库文档与 v0.3 对齐，避免团队继续按 v0.2 计划开发。

任务：

1. 新增本进度评估文档。
2. 更新 `docs/dev-plan.md` 的当前目标和优先级。
3. 清理新增源图命名，将 `ChatGPT Image ...` 改为语义化文件名。

验收：

- `docs/dev-plan.md` 明确以 v0.3 为目标。
- `assets/image` 不再出现新增的 `ChatGPT Image ...` 源图。

### 阶段 1：地图模式与生成规则

目标：建立 v0.3 普通模式 / 评委模式的入口。

任务：

1. 新增 `GameModeConfig` 概念：
   - `normal`
   - `judge`
2. 普通模式支持：
   - 随机出生点
   - 随机撤离格
   - 不生成四角固定撤离点
   - 不保留到撤离点的安全路径
3. 评委模式支持：
   - 指定地图尺寸
   - 指定出生点
   - 指定雷房 / 怪物房 / 宝箱房 / 事件房 / 撤离格
4. 将当前“中心出生 + 四角撤离 + 保底路径”保留为 legacy 或 judge 展示配置。
5. 更新自测，分别覆盖普通随机和评委手排。

验收：

- 普通模式不再默认中心出生。
- 普通模式不再默认四角撤离。
- 普通模式可生成无保底路径地图。
- 评委模式能稳定生成指定布局。

### 阶段 2：地图格状态拆分

目标：实现 v0.3 的未知 / 已扫描 / 已探索 / 已清理。

任务：

1. 在格子数据中新增：
   - `scanned`
   - `explored`
   - `cleared`
2. 关闭 `Minefield:Reveal()` 的 0 格 BFS 展开。
3. 将“玩家亲自进入”定义为 `explored = true`。
4. 将“道具或事件揭示信息”定义为 `scanned = true`。
5. 已扫描格：
   - 不可传送
   - 不触发房间事件
   - 不增加协议压力
6. 已清理格：
   - 特殊房事件完成后设置
   - 小地图显示清理状态

验收：

- 进入 0 雷数格不再自动展开周围格。
- 扫描信息可显示，但不等于探索。
- 只有亲自进入过的安全格可传送。

### 阶段 3：协议压力系统

目标：将协议从“探索房间数阈值”切换为“压力值”。

任务：

1. `Protocol` 新增：
   - `pressure`
   - `level`
   - `thresholds`
2. 首次探索未知房时增加压力。
3. 回到已探索房、传送、房间内移动、战斗走位不增加压力。
4. 协议 1 时，继续探索未知房造成额外生命损失。
5. HUD 增加压力条。
6. 结算显示最终协议等级和压力。

验收：

- 同一房间反复进出不重复增加压力。
- 传送不增加压力。
- 协议 1 只惩罚继续探索未知房。

### 阶段 4：背包、物品、仓库

目标：把 `gold + parts` 简化物资升级为 v0.3 的独立物品和负重。

任务：

1. 新增 `ItemDef`：
   - `id`
   - `name`
   - `type`
   - `weight`
   - `value`
   - `effect`
2. 新增 `InventoryState`：
   - 当前背包物品
   - 当前负重
   - 负重上限
3. 新增 `WarehouseState`：
   - 局外物品计数
   - 持久化存档
4. 搜索和宝箱产出物品。
5. 背包满时先实现“无法拾取”提示，替换 / 丢弃后移。
6. 成功撤离：背包物品全部进入仓库。
7. 失败结算：按保底规则保留部分物品进入仓库。

验收：

- 背包能显示物品和负重。
- 成功撤离后仓库增加物品。
- 失败后未保留物品丢失。

### 阶段 5：事件系统扩展

目标：从旅商单事件升级为通用事件框架。

任务：

1. 事件房保存 `eventId` 和 `completed`。
2. 首批事件：
   - 商人
   - 骰子
   - 下注怪物
3. 事件结果可影响：
   - HP
   - 金币
   - 物品
   - Buff
   - 压力
4. 事件完成后格子进入已清理。

验收：

- 同一事件房不会重复领取。
- 事件结果能正确进入背包 / 仓库 / 协议 / HP。

### 阶段 6：怪物轻量走位战斗

目标：替换当前战斗力检定，落地 v0.3 怪物房规则。

任务：

1. 怪物房生成固定怪物。
2. 怪物状态：
   - `hp`
   - `damage`
   - `attackCooldown`
   - `warningTimer`
   - `alive`
3. 玩家接触怪物触发挥剑：
   - 前摇
   - 命中帧
   - 收招
4. 玩家战斗力作为伤害。
5. 怪物攻击显示预警范围。
6. 怪物攻击命中玩家扣血。
7. 怪物死亡后掉落奖励，并标记房间已清理。

验收：

- 玩家可以穿过怪物房离开。
- 玩家可以击败怪物。
- 怪物攻击有预警和命中反馈。
- 怪物死亡后不重复刷新。

## 6. 当前建议的最近三项任务

按收益和风险排序，最近应做：

1. **完成阶段 1：地图模式与生成规则**
   - 这是 v0.3 的基础分叉。
   - 不做这个，评委模式、随机出生、随机撤离都会继续混在旧逻辑里。

2. **完成阶段 2：地图格状态拆分并关闭 0 展开**
   - 这是小地图、扫描、传送、协议压力的共同前置。

3. **完成阶段 3：协议压力系统**
   - 改动集中，且能明显体现 v0.3 主题。

背包仓库和怪物战斗都重要，但建议排在上述三项之后。
