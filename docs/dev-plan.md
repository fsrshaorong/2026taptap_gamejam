## 下一步开发顺序

### P0：立刻做

1. **失败保底结算**
   - 血量归零后进入失败面板。
   - 展示本局物资。
   - 普通难度先允许保留 1 件或固定比例金币。
   - 这是策划闭环中目前缺口最大的一块。

2. **特殊房型数据结构**
   - 在地图格子上补 `roomType`。
   - 初期支持 `normal`、`mine`、`monster`、`chest`、`event`、`exit`。
   - 所有非雷房探索后继续显示雷数。

3. **宝箱房独立化**
   - 从“安全房搜索点”升级为独立宝箱房。
   - 小地图显示宝箱图标 + 雷数。
   - 宝箱只触发一次。

4. **怪物房独立化**
   - 怪物房不计入雷数。
   - 进入后显示怪物强度和玩家战斗力。
   - Demo 可先自动结算，后续再加逃跑。

5. **雷房表现补强**
   - 踩雷时房间红闪、地图显示雷图标。
   - 已触发雷房显示为危险通路。
   - 二次进入提示“不再触发”。

### P1：强烈建议

1. **撤离确认**
   - 到撤离点后弹确认，不要按 E 直接结束。
   - 显示当前收益和风险提示。

2. **随机撤离房 Demo 版本**
   - 在非雷格中随机放 1-2 个撤离房。
   - 初始隐藏，探索后显示。
   - 是否保留四角撤离点作为临时兜底待定。

3. **事件房交易 NPC**
   - 把部分局内物资提前换成金币。
   - 金币失败不掉。
   - 限制交易次数，避免替代撤离。

4. **局内物资与金币分离**
   - 局内获得的是可带出物资。
   - 成功撤离后转金币。
   - 失败时进入保底选择。

5. **小地图图标系统**
   - 图标不能遮挡数字。
   - 普通房显示数字，特殊房显示小图标 + 数字。

### P2：时间充裕再做

多难度、出生点选择、初始带入物品、局外天赋、高级标记、多色标记、更多事件、更多怪物、多层地图、蜂窝地图、音效与演出。

## 手感打磨记录

### 2026-05-30

问题：

- 最新连续移动用固定时间间隔触发位移，视觉上有顿感。
- 单步位移过大，导致玩家移动速度偏快。

处理：

- 移动改为按帧 `dt` 连续位移。
- 房间内移动速度调为 170px/s。
- 保留门口进入相邻格逻辑。
- 墙边提示增加冷却，避免按住方向键时反复刷消息。

后续验证重点：

- 低帧率下是否仍能稳定进门。
- 房间宽高变化时速度是否舒适。
- 按住方向键贴墙是否还有顿挫或提示干扰。

## 当前技术优先级

1. 先保持现有最小可玩闭环稳定。
2. 每次只把一个策划差异变成可验证系统。
3. 优先补影响核心体验的系统：失败保底、特殊房型、小地图图标。
4. 出生点选择、随机撤离点、局外成长暂缓，避免 Demo 骨架失稳。

## 验证命令

当前环境没有本机 Lua，可用 npm 临时运行 Fengari 执行 Lua 自测：

```powershell
npm.cmd exec --yes --package=fengari-node-cli -- fengari scripts\tests\minefield_selftest.lua
```

也可用 `luaparse` 做语法解析：

```powershell
npm.cmd exec --yes luaparse -- scripts/main.lua scripts/systems/ExtractionRun.lua scripts/systems/Protocol.lua scripts/tests/minefield_selftest.lua
```
