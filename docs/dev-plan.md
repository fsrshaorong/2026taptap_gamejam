# 开发计划与里程碑

## 当前目标

把玩法从旧灯塔解谜切换为“扫雷地图 + 地牢房间 + 搜打撤”。

核心优先级：

1. 先保证扫雷地图生成和撤离逻辑正确。
2. 再做左上角小地图和放大地图。
3. 再做房间场景与四方向门移动。
4. 最后补搜刮、危险房、撤离表现。

---

## Phase 2：地图 UI

**目标**：左上角显示完整扫雷小地图，并支持点击放大。

| # | 任务 | 说明 |
|---|------|------|
| 2.1 | 小地图绘制 | 左上角显示整张扫雷地图 |
| 2.2 | 格子状态显示 | 未探索、数字、空白、旗标、玩家位置、撤离点 |
| 2.3 | 玩家位置同步 | 玩家换房间后，小地图当前位置立即更新 |
| 2.4 | 点击放大 | 点击小地图打开放大地图界面 |
| 2.5 | 放大地图交互 | 支持查看、插旗、取消插旗 |
| 2.6 | 已经过房间回传 | 点击已经进入过的安全格，传送回对应房间 |
| 2.7 | 地图关闭 | 返回房间视图，不改变玩家位置 |

**交付标准**：

- 玩家能看懂整张扫雷图。
- 当前所在格醒目。
- 四角撤离点始终可见。
- 放大地图可以用于规划路线。
- 已经经过的安全房间可以作为回传点。

---

## Phase 3：房间与门

**目标**：主画面变成当前格子的房间场景，通过门移动到相邻格。

| # | 任务 | 说明 |
|---|------|------|
| 3.1 | 房间场景骨架 | 一个房间画面，显示玩家和房间背景 |
| 3.2 | 四方向门 | 根据地图边界显示上/下/左/右门 |
| 3.3 | 门到坐标映射 | 上门 y-1，下门 y+1，左门 x-1，右门 x+1 |
| 3.4 | 移动触发翻格 | 进入未探索格时调用扫雷 Reveal |
| 3.5 | 已探索房间回访 | 回到已探索房间不重复触发危险 |
| 3.6 | 插旗门提示 | 相邻格插旗后，对应门显示危险标记 |
| 3.7 | 回传同步房间 | 传送到已经过房间后，主场景刷新为该格房间 |

**交付标准**：

- 玩家不能在地图上瞬移，只能通过门移动。
- 例外：已经亲自经过的安全房间可以通过放大地图回传。
- 门和扫雷坐标严格对应。
- 房间移动后，小地图状态同步。

## Phase 4：危险房与搜刮

**目标**：把“地雷”表现为可感知的危险房，并加入最小搜打撤收益循环。

| # | 任务 | 说明 | 状态 |
|---|------|------|------|
| 4.1 | 危险房触发 | 进入地雷格触发失败/受伤/战斗中的一种 | 完成：当前为直接失败 |
| 4.2 | 安全房搜索点 | 安全房生成可搜刽物件 | 完成：房间内资源箱 |
| 4.3 | 基础资源 | 金币、零件、补给等简单收益 | 完成：金币、零件 |
| 4.4 | 背包/收益记录 | 记录本局已获得资源 | 完成：HUD 显示 |
| 4.5 | 撤离结算 | 到四角撤离点后带走收益 | 完成：撤离面板结算 |

**第一版建议**：

- 地雷房先做成直接失败或扣大量血。
- 搜刮先只做 1 种资源。
- 不先做复杂战斗，避免 48h 版本失焦。

---

## Phase 5：表现打磨

**目标**：让地图、房间和风险反馈清楚、有紧张感。

| # | 任务 | 说明 |
|---|------|------|
| 5.1 | 数字可读性 | 小地图数字颜色按经典扫雷区分 |
| 5.2 | 房间氛围 | 数字越高，房间越危险 |
| 5.3 | 门反馈 | 未知门、已探索门、插旗门表现不同 |
| 5.4 | 撤离点表现 | 四角房间有明确撤离装置 |
| 5.5 | 音效 | 开门、翻格、插旗、踩雷、撤离 |

## 模块职责建议

```text
scripts/
├── main.lua
├── systems/
│   ├── Minefield.lua       # 扫雷地图核心
│   ├── ExtractionRun.lua   # 玩家、移动、撤离状态
│   ├── RunInventory.lua    # 本局金币/零件/搜索记录
│   └── GameState.lua       # 后续可改为局内总状态
├── scenes/
│   └── DungeonRoom.lua     # 当前房间表现与门交互
└── ui/
    ├── MiniMap.lua         # 左上角小地图
    └── MapOverlay.lua      # 点击放大的扫雷地图
```

旧文件 `Lighthouse.lua`、`ButtonSystem.lua`、`DayManager.lua` 属于上一版灯塔玩法，后续可以逐步替换或废弃。
