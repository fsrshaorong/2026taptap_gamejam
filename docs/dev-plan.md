# 开发计划与里程碑

## 总体路线（按优先级）

```
Phase 1: 骨架搭建（先能跑起来）
Phase 2: 核心循环（能玩一天）
Phase 3: 五天流程（完整循环）
Phase 4: 打磨（视觉/音效/体验）
```

---

## Phase 1：骨架搭建

**目标**：游戏能运行，能看到灯塔场景，有基础 UI 框架。

| # | 任务 | 说明 |
|---|------|------|
| 1.1 | 项目架构搭建 | main.lua 入口、模块划分、状态管理框架 |
| 1.2 | 灯塔场景绘制 | 用 NanoVG 画出灯塔、水车、电缆等组件的像素/简笔画版本 |
| 1.3 | 底部按钮栏 UI | 5 个按钮（停/反/连/切/换）能显示、能点击 |
| 1.4 | 诊断文本框 UI | 底部或侧边文本框，能显示提示信息 |

**交付标准**：能看到场景 + 5 个按钮 + 文本框，点按钮有文字反馈。

---

## Phase 2：核心循环（Day 1 可玩）

**目标**：Day 1 完整可玩，按钮能操作场景组件，有状态变化。

| # | 任务 | 说明 |
|---|------|------|
| 2.1 | 场景状态机 | 组件状态定义（灯塔亮/灭/过载 等），状态转换逻辑 |
| 2.2 | 按钮→组件交互 | 每个按钮对每个组件的作用效果 |
| 2.3 | 操作预报 | 悬浮/选中按钮时显示「结果」和「风险」 |
| 2.4 | Day 1 胜利条件 | 灯塔亮起 → Day 1 完成 |
| 2.5 | 删除按钮流程 | Day 结束 → 选择删除一个按钮 → 删除预报 → 确认 |

**交付标准**：能玩完 Day 1，能删除一个按钮进入 Day 2。

---

## Phase 3：五天完整流程

**目标**：5 天全部可玩，有状态继承，有结局。

| # | 任务 | 说明 |
|---|------|------|
| 3.1 | Day 切换系统 | 天数推进、场景状态继承、后果生成 |
| 3.2 | Day 2~4 后果逻辑 | 根据前一天解法生成新问题 |
| 3.3 | Day 5 结局 | 最后一个按钮决定结局，2~3 种结局文本/画面 |
| 3.4 | 当天重置 | 允许重来当天，不回滚跨天状态 |
| 3.5 | 保底出口 | 确保每天至少有一条路能走通 |

**交付标准**：能从 Day 1 玩到 Day 5，看到结局画面。

---

## Phase 4：打磨

**目标**：视觉、音效、体验优化。

| # | 任务 | 说明 |
|---|------|------|
| 4.1 | 每日色调变化 | Day 1 清晨 → Day 5 近黑白 |
| 4.2 | 组件状态动画 | 漏电火花、灯光闪烁、雨滴等 |
| 4.3 | 音效 | 按钮点击、状态变化、环境音 |
| 4.4 | 结局表现 | 结局画面 + 文案 + 世界地图暗示 |
| 4.5 | 开头引导 | 简短开场文案或动画 |

---

## 第一步：Phase 1.1 — 项目架构

立即要做的事：

```
scripts/
├── main.lua              # 入口：初始化、事件分发
├── systems/
│   ├── GameState.lua     # 全局状态管理（天数、按钮、组件状态）
│   ├── ButtonSystem.lua  # 五按钮逻辑
│   └── DayManager.lua    # 天数切换、后果生成
├── scenes/
│   └── Lighthouse.lua    # 灯塔场景（组件绘制+交互）
└── ui/
    ├── ButtonBar.lua     # 底部按钮栏
    └── InfoPanel.lua     # 诊断文本框
```

先把框架搭好，每个模块有明确职责，后续填充逻辑不会乱。
