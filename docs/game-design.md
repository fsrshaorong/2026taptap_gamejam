## 一、核心概念

### Pitch（一句话）

> 你有五个按钮维护一座灯塔。每天失去一个按钮。系统会告诉你眼前会失去什么，但不会告诉你明天会坏成什么。第五天，你只剩一个按钮，面对自己留下的世界。

### 主题契合

主题「五四三二一」体现为操作权的逐日递减：

- Day 1：5 个按钮
- Day 2：4 个按钮
- Day 3：3 个按钮
- Day 4：2 个按钮
- Day 5：1 个按钮

核心体验不是"越来越强"，而是：

> **解决问题的方式越来越少，而场景却越来越像玩家自己造成的样子。**

---

## 二、核心玩法结构

同一个灯塔场景持续五天。玩家每天拥有的操作按钮减少一个。前一天的解法会改变后一天的场景。第五天只剩一个按钮，玩家要面对前四天留下的所有后果。

```
Day 1：5 个按钮，完整操作，完成基础任务
Day 2：4 个按钮，出现 Day 1 行为导致的后果
Day 3：3 个按钮，后果叠加，开始无法完美解决
Day 4：2 个按钮，玩家需要做明确取舍
Day 5：1 个按钮，用最后一个操作完成最终选择
```

每天结束时，玩家必须删除一个按钮。删除后，该按钮从后续天数中永久移除。

## 三、五个按钮设定

| 按钮 | 动词 | 作用对象 |
|------|------|---------|
| **停** | 停止 | 机器、水流、灯光旋转、过载状态 |
| **反** | 反转 | 水流方向、灯光方向、机械方向 |
| **连** | 连接 | 电缆、管道、控制节点 |
| **切** | 切断 | 线路、隔离危险、断开系统 |
| **换** | 交换 | 电池、组件位置、资源归属 |

设计原则：

- 按钮作用于**场景组件**，不是角色动作
- 每个按钮都有直接功能和后果
- 删除按钮 = 失去一种解决问题的语言
- 第五天最后留下的按钮决定最终表达方式

### 最终按钮决定结局

| 最后留下 | 最终操作 |
|---------|---------|
| 连 | 连接两个系统，共享最后电力 |
| 切 | 切断一个牺牲对象 |
| 反 | 反转灯光方向，选择照向何方 |
| 停 | 停止过载，可能也停止灯塔 |
| 换 | 交换被拯救与被牺牲的对象 |

## 五、五天任务设计

### Day 1：点亮灯塔（教学日）

**目标**：让灯塔亮起来。

多种解法：
- 用「连」接通主电缆
- 用「切」切断故障线路
- 用「反」反转水车供电方向
- 用「停」停止过载机器
- 用「换」替换备用电池

不同解法都能完成 Day 1，但会给 Day 2 留下不同后果。

### Day 2：稳定系统

根据 Day 1 主要解法产生变化：

| Day 1 解法 | Day 2 后果 |
|-----------|-----------|
| 用「连」强行接主电缆 | 出现漏电/过载 |
| 用「切」拆掉线路 | 村庄局部断电 |
| 用「反」反转水车 | 水流改道 |
| 用「停」暂停机器 | 机器卡死 |
| 用「换」换电池 | 备用电池缺失 |

**目标**：稳定灯塔系统，避免过载或严重损坏。

### Day 3：无法完美

核心主题显现：**玩家可能已无法同时保住所有目标。**

需要在以下目标中取舍：
- 保住灯塔
- 保住村庄
- 救海面船只

### Day 4：最终导向

只剩 2 个按钮。偏策略选择，非复杂谜题。

可能方向：
- 照向海面 → 救船
- 照向村庄 → 保护村庄
- 照向山路 → 引导撤离
- 关闭灯塔 → 避免过载爆炸

### Day 5：只剩一个按钮

极简、强烈情绪、主题表达。玩家用最后一个按钮完成最终决定。

## 六、后果继承系统

### 关键状态变量

```lua
game_state = {
    day = 1,
    day1_repair_method = nil,  -- "connect"/"cut"/"reverse"/"stop"/"swap"
    deleted_buttons = {},
    cable_state = "stable",     -- stable/broken/overload
    battery_state = "full",     -- full/empty/broken
    village_state = "safe",     -- safe/dark/burning
    lighthouse_state = "off",   -- on/off/overload
    sea_state = "calm",         -- calm/storm/lost
}
```

### 设计原则

- 只记录「关键选择」，不遍历全部操作
- 48h 版本做「半真实分支」：玩家感觉选择有影响，实际只检测几个关键变量
- 每天只需 2~3 种明显变化即可

## 七、操作预报 / 删除预报机制

### 操作预报

鼠标悬浮按钮时显示：

```
【连接主电缆】
结果：灯塔将获得电力。
风险：主电缆当前不稳定，继续使用可能留下过载隐患。
```

### 删除预报

每天结束选择删除按钮时显示：

```
【删除：连】

当前依赖：
[!] 主电缆仍需要「连」才能稳定供电。
[-] 备用线路尚未接入。
[-] 村庄线路仍有 1 个断点。

未知：
明天新增的故障不会被预报。
```

**重要原则**：删除前只显示当前已有依赖，不显示下一天新生成的问题。

## 八、公平性与提示设计

1. 每天允许「当天重置」
2. 跨天后果不可轻易回滚
3. 每天至少有一个保底出口
4. 不让玩家彻底卡死
5. 失败不写「失败」，写「无法完整修复」

每天三层目标：

| 层级 | 描述 |
|------|------|
| 最低 | 进入下一天 |
| 普通 | 完成当天任务 |
| 完美 | 不留下严重后遗症 |

## 十一、扩展前景（48h 后）

完整版可扩展为多个五日关卡：

```
第 1 关：灯塔 —— 决定海路撤离
第 2 关：车站 —— 承接撤离人口
第 3 关：水坝 —— 决定供水与防洪
第 4 关：温室 —— 决定粮食与种子
第 5 关：广播塔 —— 决定信息传播与世界记忆
```

前一关结局影响后一关初始条件，最终所有关卡结果组合成完整世界结局。

48h 版本在结尾用地图暗示后续：

```
灯塔：已记录
车站：等待信号
水坝：等待调度
温室：等待供能
广播塔：等待播报
```
